**B1b. `[INCOMPLETE — Low]` The "mirrored defaults" are already stale.** `subtitleStyles.ts:2-6` claims to mirror `subtitle_gen.default_styles()` and says to keep them in sync, but the two disagree on font and size (Tahoma 66/46 at `subtitleStyles.ts:45-107` vs the runtime "Noto Naskh Arabic" 64 / "Leelawadee UI" 44 from `settingsStore.ts:185-205`). Runtime parity is saved only because overrides are always sent; the documented invariant is false.

#### B2. Line wrapping — the largest preview-vs-output break

- `[BUG — High]` **Thai text is never actually wrapped.** `wrapSubtitleText` splits on ASCII spaces (`Step3Subtitles.tsx:60` — `const words = line.split(" ")`). Thai script has no inter-word spaces, so for typical Whisper Thai output `words` is a single element, `current.length + 1 + word.length <= maxChars` fails immediately, and the text is emitted as one unbroken line. No `\N` is inserted.
- `[BUG — High]` **The `.ass` cannot compensate.** The header sets `WrapStyle: 2` (`subtitle_gen.py:233`), which disables libass's automatic wrapping — only explicit `\N` breaks. `escape_ass_text` converts `\n` → `\N` (`subtitle_gen.py:113-118`), but there are none. A >40-character Thai caption therefore renders as **one line overflowing the 1080 px frame** in the exported MP4, while the browser preview wraps it automatically with CSS and looks correct. Plan line 77's "Smart Auto-Line Wrapping at a configurable `Max Characters Per Line` (default `40 chars`)" is effectively unimplemented for the language it targets.
- `[INCOMPLETE — Medium]` The width is not even configurable: Step 3 reads `editor.maxCharsPerLine` (`Step3Subtitles.tsx:255,288,305,469`) which has no UI, while the visible control writes the unread `thai.maxCharsPerLine` (`SettingsDrawer.tsx:848-863`) — already reported in Step 1 §B3; it compounds this defect.
- `[OK]` Arabic is intentionally excluded from character wrapping (`Step3:305` wraps Thai only), which is correct for RTL.

#### B3. Positioning, stacking and RTL

- `[OK]` **Stacking is structurally equivalent.** The backend emits up to two `Dialogue` events per cue, one per style (`subtitle_gen.py:266-275`), both `Alignment 2` (bottom-centre, `:199`) at their own `MarginV` (252 Arabic / 150 Thai, `:135,:146`). The preview draws two absolutely-positioned lines with independent `bottom` offsets (`Step3Subtitles.tsx:198-237`). Same model, same numbers.
- `[OK]` **RTL is handled.** Preview sets `dir="rtl" lang="ar"` (`Step3:543-544`, `:200-201`); the `.ass` carries no RTL override because libass applies the Unicode bidi algorithm itself, and because Arabic and Thai are split into separate `Dialogue` events (`subtitle_gen.py:266-275`) there is no mixed-direction line to mis-order.
- `[INCOMPLETE — Low]` **Vertical anchoring differs by half-leading.** CSS `bottom: marginV * scale` (`Step3:204`) positions the *element box's* bottom edge, which includes the extra leading created by `lineHeight: 1.35` (`Step3:209`); libass anchors the *text's* bottom at `MarginV`. With Harakat-heavy Arabic the preview's glyphs sit slightly higher than the burned output.
- `[INCOMPLETE — Low]` **Preview adds its own side padding.** Both preview lines carry `px-2` (`Step3:202,222`) on top of `left/right` margins derived from PlayRes, so the effective horizontal inset is larger than `MarginL/R`.
- `[INCOMPLETE — Low]` **The overlap warning is not verifiable from the output.** `stylesOverlap` compares `arabic.marginV` against `thai.marginV + thai.size * thai.lineHeightPad` (`subtitleStyles.ts:165-172`), then the UI asserts "Lines are N px apart **in the burned-in file**" (`Step3:634-637`). The figure is computed from a preview-only value (see B5), so the claim cannot hold for the rendered video.
- `[INCOMPLETE — Low]` **Overlapping cues are neither prevented nor flagged.** Seeded cues come straight from Whisper segments (`Step3:281-289`), which can overlap; two cues active at once produce two `Dialogue` events at the same `MarginV` and collide on screen.

#### B4. Timing and format

- `[OK]` `subtitle_timebase: "clip"` (`Step4Export.tsx:447`) matches clip-relative cues (`Step3:285-286`); the backend offsets by `clip.start` only for `"source"` (`main.py:863-877`), so the `"clip"` path is a no-op offset — correct.
- `[OK]` Cue ends are truncated to the clip duration (`subtitle_gen.py:261-264`, `main.py:895,920`), and ASS/SRT timestamps use the correct `H:MM:SS.cc` / `HH:MM:SS,mmm` formats (`subtitle_gen.py:97-110`).
- `[OK]` The `.srt` sidecar emits Arabic then Thai (`subtitle_gen.py:307-311`), matching the plan's stacked order.
- `[BUG — Low]` **ASS timestamps can be invalid.** `format_ass_time` formats `secs = total % 60` with `%05.2f` (`subtitle_gen.py:97-102`), so a cue boundary in the 59.995–59.999 s window rounds up to `0:00:60.00` — an out-of-range ASS time field (verified by executing the function).
- `[INCOMPLETE — Low]` **Text escaping is incomplete.** `escape_ass_text` escapes only `{` and `}` (`subtitle_gen.py:113-118`); a literal `\N`, `\h` or `\n` typed by the editor is interpreted as an ASS override by libass, and the preview shows it as plain text.
- `[INCOMPLETE — Low]` **`.srt` is written with platform newlines.** `write_ass` pins `newline="\n"` (`subtitle_gen.py:289`) but `write_srt` does not (`:327`), so Windows produces CRLF `.srt` files while the `.ass` stays LF.
- `[INCOMPLETE — Low]` `AssDocument.cue_count` counts emitted `Dialogue` lines, not cues (`subtitle_gen.py:270,275`), so a 10-cue bilingual clip reports 20.
- `[OK]` Colour conversion is correct: `#RRGGBB` → `&HAABBGGRR` with the BGR swap (`subtitle_gen.py:79-94`); verified `#dcb46e` → `&H006EB4DC`, `#f4f4f1` → `&H00F1F4F4`, and the preview uses the identical hex values (`settingsStore.ts:188,199`).

#### B5. Harakat padding, box opacity and outline colour — controls that stop at the preview

The Settings control "Harakat line-height padding" (`SettingsDrawer.tsx:731-749`) therefore changes the preview and **nothing in the burned video** — the opposite of plan line 82's requirement. The real lever in `.ass` (increasing Arabic `margin_v`/line spacing) is not exposed.
- `[MISSING — Medium]` **Box opacity is dead end-to-end.** `boxOpacity` exists in the store (`settingsStore.ts:191,202`) and both sliders (`SettingsDrawer.tsx:770-788,884-902`), but never reaches `subtitleStyles.ts`, `StyleSpec`, or `subtitle_gen`. ### C. Edge Cases & Error Handling

#### C1. Empty / degenerate transcripts

- `[OK]` Whisper drops blank segments before storing (`transcriber.py:352-366`), so a silent lecture yields `segments: []` rather than empty strings; the store accepts it (`projectStore.ts:140-147`) and Step 3 renders an explicit empty-cue state (`Step3:477-486`).
- `[INCOMPLETE — Medium]` **No empty-transcript guard before discovery.** Step 2 auto-fires `/discover-clips` as soon as a `transcriptId` exists (`Step2Discovery.tsx:464-470`); with zero segments `_format_transcript` returns `""` (`analyzer.py:216-229`), so the model receives an empty `TRANSCRIPT:` section (`analyzer.py:271-273`). The user sees "No clips proposed yet" (`Step2Discovery.tsx:707-714`) instead of "Whisper found no speech".
- `[INCOMPLETE — Low]` A zero-duration record also disables clip clamping (`analyzer.py:314-316` — `if duration > 0`), so proposals are accepted unchecked and then fail at render.
- `[BUG — Medium]` **Zero/unknown duration can emit invalid JSON.** Because the clamp is inside `if duration > 0` (`analyzer.py:314`), a model reply of `{"start": -5, "end": 30}` or `{"start": NaN}` passes through unchanged; `ClipProposal` (`main.py:198-202`) has no `ge/gt` bounds and Python's `json.dumps` emits bare `NaN`/`Infinity` (invalid JSON). The browser's `response.json()` then throws and `api.ts:85-89` mislabels it "Cannot reach the FastAPI sidecar on 127.0.0.1:8008. Is backend.exe running?" — a transport message for a data error.
- `[INCOMPLETE — Low]` Segments that become empty *after* glossary replacement are kept: `apply_glossary` collapses whitespace (`transcriber.py:200-211`) and `apply_glossary_to_segments` has no empty filter (`:214-228`), so blank segments are stored and returned; only the LLM prompt drops them (`analyzer.py:222-223`).

#### C2. Malformed JSON from Ollama / Cloud LLMs

- `[OK]` `extract_json` strips ```json fences, retries on the outermost `{…}` span, and rejects non-objects with distinct messages (`analyzer.py:173-190`). Missing `clips` → `LLMError` (`:376-378`); missing `verified_text` → `LLMError` (`:429-431`).
- `[OK]` **No single bad clip can fail a request.** Non-dict entries, non-numeric times, inverted ranges, `< 1 s`, `> 1.5 × max_duration`, `< 0.5 × min_duration` and excluded-range overlaps are skipped (`analyzer.py:304-324`); mutual overlaps are deduped keeping the earliest (`:337-344`); the list is capped (`:346`); titles/rationales are coerced and truncated (`:326-333`).
- `[OK]` Provider failures are actionable: HTTP errors include status + first 400 chars (`analyzer.py:150-153`), network/timeout → "Could not reach the LLM at …" (`:145-148`), Ollama's `response_format` 400 → automatic plain retry (`:139-144`), missing model → explicit configuration error (`:92-96`). All map to 502 (`main.py:401-403`).
- `[BUG — Medium]` **Cloud STT failures escape as raw 500s.** The cloud path has no `try/except` around the HTTP call and an unguarded `response.json()` (`transcriber.py:413-428`), so a connection error, read timeout or non-JSON body becomes an unhandled exception → plain-text `500 Internal Server Error` instead of the intended `TranscriptionError` → 503 (`main.py:396-398`). HTTP status ≥ 400 *is* handled (`transcriber.py:422-426`).
- `[INCOMPLETE — Low]` **No retry/backoff anywhere** — only the single documented `response_format` retry (`analyzer.py:139-144`); 401/403/429/5xx and timeouts are terminal, and truncated completions are not detected (no `finish_reason` check at `:155-161`), so a length-capped reply is reported as "invalid JSON".
- `[INCOMPLETE — Low]` **Audio extraction has no timeout.** `extract_audio` runs `subprocess.run(...)` without `timeout` (`transcriber.py:180-187`); a wedged FFmpeg blocks the request until the frontend's 30-minute cap (`api.ts:184`).
- `[INCOMPLETE — Low]` The cloud STT timeout is hard-coded to 300 s (`transcriber.py:398`) and is not settable from the request (`main.py:511-519`).
- `[BUG — High]` **Discovery only ever sees the tail of a long lecture.** `_format_transcript` caps at 24,000 characters and keeps the **last** slice: `joined = joined[-max_chars:]`, comment "Keep the tail: editors usually refine the unclaimed second half" (`analyzer.py:216-229`). A 1–3 h Tafseer lecture transcribes to roughly 40k–90k characters, so the first 20–60 % of the lecture is invisible to the reasoning model and can never yield a clip — directly contradicting plan line 69 ("instructs the LLM to search only the unclaimed segments of the lecture"). The cut also lands mid-line, so the first entry of the prompt is a fragment like `ะฮฺ] …`. No chunking, windowing, or multi-pass fallback exists.

#### C3. Windows forbidden filename characters

- `[OK]` **Character handling matches exactly.** Frontend `FORBIDDEN = /[<>:"/\\|?*]/g` plus a code-point walk for U+0000–U+001F (`filenameTemplate.ts:11-25`); backend `[<>:"/\\|?*\x00-\x1f]` (`main.py:632`). Both trim, strip trailing dots, collapse whitespace, cap at 150 chars, and fall back (`filenameTemplate.ts:28-33` vs `main.py:631-634`).
- `[OK]` **Token substitution is identical**: `{LectureName}`, `{Title}`, `{Clip}`, `{Resolution}` and generic `{NN}`/`{NNN}` (`filenameTemplate.ts:68-78` vs `main.py:801-813`); `{Title}` is sanitized before substitution on both sides; the `.mp4` fallback (`filenameTemplate.ts:90` vs `main.py:838-839`) and the duplicate-name guard that appends `_NN` using `index + 1` (`filenameTemplate.ts:91-96` vs `main.py:906-910`) agree in parity — though the shared guard logic is itself incomplete (see the duplicate-name bullet below).
- `[MISSING — Medium]` **Windows reserved device names are unhandled on both sides.** `CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9` (and names ending in dot/space) pass through both sanitizers, so a clip titled "CON" produces an unwritable path at render time.
- `[INCOMPLETE — Low]` **Absolute `output_path` is trusted verbatim**: `clip.output_path` is accepted, its parent `mkdir`'d, and only the basename sanitized (`main.py:824-828`). The UI never sends it, but a hand-edited `.tafseer` can direct renders anywhere on disk.
- `[BUG — Low]` **The duplicate-name guard suffixes only once and never re-checks** — identical on both sides (`filenameTemplate.ts:91-97`, `main.py:906-910`). A clip titled `Intro_03` followed by a clip titled `Intro` still produces two `Intro_03.mp4` files, and the second overwrites the first (`-y` at `renderer.py:227`).
- `[BUG — Low]` **A third, divergent sanitizer drives the Settings preview.** `sanitizeFileNameTemplate` (`SettingsDrawer.tsx:220-226`) replaces forbidden characters with `-` instead of `_`, uses a different zero-pad regex (`\{(\d+)\}`), and knows nothing about `{Clip}`/`{Resolution}` — so the "sanitized template" shown in Settings does not match what Step 4 or the sidecar will produce.
- `[INCOMPLETE — Low]` Residual Windows path hazards remain on both sides: trailing spaces survive the sanitizers, `MAX_PATH` (260) is never considered for `output_dir + name`, and the JS 150-character cap counts UTF-16 units (`filenameTemplate.ts:32`) where Python counts code points (`main.py:634`), so an emoji-heavy title can be truncated differently — even mid-surrogate-pair — in the preview versus the actual filename.
- `[INCOMPLETE — Low]` Project filenames use a *different*, weaker sanitizer: `suggestProjectFileName` (`projectFile.ts:33-40`) only maps `[\\/:*?"<>|]` → `-` and caps at 80 chars, with no control-character, reserved-name, or trailing-dot handling.

#### C4. Offline backend states

- `[OK]` Health polling is guarded against overlap and runs every 15 s (`settingsStore.ts:706-732`, `App.tsx:33-39`); the header shows a status pill with VRAM/NVENC detail (`StepperHeader.tsx:102-118`); Step 1 and Step 4 render offline banners with a Retry button (`Step1Ingest.tsx:832-847`, `Step4Export.tsx:877-892`).
- `[INCOMPLETE — Medium]` Step 2 and Step 3 have no offline affordance — failures appear only as transient toasts (`Step2Discovery.tsx:455-458`, `Step3Subtitles.tsx:373-376`).
- `[INCOMPLETE — Medium]` Offline render shows the raw browser error rather than the sidecar message (A2.5).
- `[INCOMPLETE — Medium]` **No action is actually gated on `sidecar.status`.** Transcribe is gated only by `sourcePath`/cloud config (`Step1Ingest.tsx:504-519,852`), Step 2 never reads the sidecar state at all (guard is `transcriptId`, `Step2Discovery.tsx:378-381`), and the Render button is never disabled for offline (`Step4Export.tsx:235-247,902-905`). The banners are purely informational, so every action is still clickable and fails after a round trip.
- `[INCOMPLETE — Low]` **The status indicator flickers on every poll.** Each 15 s `refreshHealth` sets `status: "checking"` (`settingsStore.ts:709`) before the result arrives, so the header dot animates amber/pulsing once per interval (`StepperHeader.tsx:19-21`).
- `[OK]` No automatic request retries exist (intentional); the health poll is the only recurring call.

#### C5. Render / SSE edge cases

- `[BUG — High]` **A stream that closes without `done` leaves Step 4 stuck "running" forever.** `streamRenderBatch` resolves when the reader reports `done` (`api.ts:508-520`); `runRender` has no post-loop finalizer — the `try/catch/finally` at `Step4Export.tsx:434-468` only clears the abort ref. If the sidecar dies mid-batch or a proxy truncates the response, no `done` event arrives, `job.status` stays `"running"`, the Cancel button and "Encoding with FFmpeg inside the sidecar…" footer (`:897-912`) never clear, and the user must cancel manually.
- `[OK]` Per-clip failures are isolated and reported with FFmpeg's last three stderr lines (`renderer.py:369-371` → `main.py:1023-1038` → `clip_error` → `Step4Export.tsx:397-411`).
- `[OK]` Client abort stops FFmpeg: `GeneratorExit` → `process.kill()` (`renderer.py:361-364`).
- `[OK]` Pre-flight checks: 503 when ffmpeg is missing (`main.py:1078-1082`), 400 for a missing source (`main.py:787-788`), `RenderError` for a missing `.ass` (`renderer.py:388-389`), NVENC→libx264 re-run with a `fallback` event (`renderer.py:391-412`).
- `[INCOMPLETE — Low]` An invalid hex colour from a corrupted settings backup reaches `ass_color`, which raises `ValueError` (`subtitle_gen.py:94`) inside `_prepare_clips` *before* streaming starts (`main.py:1085`) → unhandled 500 with no detail.
- `[INCOMPLETE — Low]` `output_dir` is created blindly (`main.py:792-798`); an unwritable path raises `OSError` → unhandled 500.
- `[INCOMPLETE — Medium]` **NVENC is attempted even when `/health` says it is unavailable.** `render()` gates on `encoder_available("h264_nvenc")` — the *compiled-in* probe (`renderer.py:392`, `:39-57`) — while `/health` reports the *real* probe `nvenc_available()`, which performs a one-frame test encode (`renderer.py:60-101`, `main.py:424`). A machine with a broken driver therefore reports `nvenc_available: false` in the UI (`Step4Export.tsx:746-748`) yet still pays a full failed NVENC encode before the CPU retry (`renderer.py:397-412`).
- `[INCOMPLETE — Medium]` **No per-clip FFmpeg watchdog.** The only timeouts are the probe calls (`renderer.py:51,95,451`) and `reader.join(timeout=5)` (`:367`); a hung FFmpeg blocks the SSE stream indefinitely (`-t` bounds output length, not wall-clock, `:230-231`).
- `[INCOMPLETE — Low]` **No codec/container preflight.** `probe_media` exists (`renderer.py:428-459`) but is never called, so an unreadable/wrong-codec source surfaces only as a generic `clip_error` containing the last three FFmpeg stderr lines (`:369-371`).
- `[INCOMPLETE — Low]` **Progress can go negative or jump.** `ratio = min(1.0, out_time_us / 1e6 / total)` has no lower clamp and only catches `ValueError`, so a negative `out_time_us` yields negative `clip_progress` and `float("nan")` is accepted (`renderer.py:341-347`); `main.py:1000` then propagates a negative `overall` into the SSE payload.
- `[INCOMPLETE — Low]` **FFmpeg is run at `-loglevel error` with `-nostats`** (`renderer.py:223-226,257`), so libass font/shaping warnings never reach `clip_error.detail` — the most likely cause of a wrong-typeface burn is invisible in the UI.
- `[INCOMPLETE — Low]` **Foreground scale has no height cap.** `scale={width}:-2` (`renderer.py:149`) lets a tall source (e.g. 1080×2400) exceed the 1920 px frame; `overlay=(W-w)/2:(H-h)/2` then clips top/bottom with no `crop`/`pad` on `[fg]`.

#### C6. State, persistence and autosave

- `[OK]` `.tafseer` parsing is defensive: JSON errors, format tag, and newer `schemaVersion` are rejected with clear messages (`projectFile.ts:197-213`); every number passes through `num()` so `NaN`/`Infinity` become defaults (`:61-63`); clips are clamped non-negative (`:110-129`); discovery bounds are clamped to exactly the backend's own limits (`:69-85`); export settings are coerced (`:180-191`); `step` is normalized (`:95-97`).
- `[OK]` Settings rehydration is field-by-field with defaults and never persists sidecar state (`settingsStore.ts:734-743`); a corrupt autosave returns `null` and the UI toasts "Auto-save not found" (`projectStore.ts:283-289`, `RecentProjectsDrawer.tsx:101-105`).
- `[BUG — Medium]` **Deleting every style/prompt preset is undone on restart.** `coercePresets` and `coercePromptPresets` fall back to the built-in defaults when the persisted array is empty (`settingsStore.ts:423,464`), while `coerceGlossary` correctly preserves `[]` (`:440`). A user who removes all presets sees them return after a relaunch.
- `[BUG — Medium]` **A persisted-settings version bump silently destroys configuration.** Both stores declare `version: 1` with no `migrate` (`settingsStore.ts:736`, `projectStore.ts:306`); zustand logs a console error and **discards** the payload on a version mismatch — including API keys, glossary, fonts and presets. Corrupt persisted JSON is likewise dropped with no log and no UI notice (no `onRehydrateStorage`/custom storage anywhere).
- `[BUG — Low]` **`normalizeProject` accepts non-finite durations.** `typeof project.duration === "number" ? project.duration : null` (`projectFile.ts:168`) lets `NaN`/`Infinity` through, unlike every other numeric field which uses `num()` (`:61-63`). Downstream `project.duration ?? 0` (`Step2Discovery.tsx:303`) does not catch `NaN`, and `WaveformBar` only guards `duration <= 0` (`WaveformBar.tsx:150`), not non-finite values.
- `[BUG — Low]` **The forward-version guard is bypassable.** `num(payload.schemaVersion, 0) > PROJECT_SCHEMA_VERSION` (`projectFile.ts:207`) coerces a string `"2"` to `0`, so a file from a future version is accepted and silently re-normalized instead of rejected.
- `[INCOMPLETE — Low]` Normalizers are permissive: cues may be negative/inverted (`projectFile.ts:99-108`), clips may be zero-length or have `speechEnd > end` (`:110-129`), transcript segments may be unsorted/negative with a `NaN` probability (`:131-145`), and `selectedClipId` may dangle while orphan `subtitles` keys survive (`:155-160,178`).
- `[INCOMPLETE — Low]` **Orphan autosaves are never pruned.** `upsertRecent` slices the list to 8 (`projectStore.ts:66-69`) without deleting the evicted `localStorage` entry, and `listAutosavedProjectIds` (`projectFile.ts:390-401`) has no caller — so autosave snapshots accumulate until the quota is hit (see the silent-failure bullet below).
- `[INCOMPLETE — Low]` **A brand-new project appears in Recent before any snapshot exists.** `createProject` inserts a recents entry immediately (`projectStore.ts:109-114`), so clicking it before the first autosave shows the misleading "Auto-save not found — removed from local storage" toast (`RecentProjectsDrawer.tsx:101-105`, `Step1Ingest.tsx:455-457`).
- `[INCOMPLETE — Medium]` **Autosave failures are silent.** `writeAutosave` swallows quota/security exceptions and returns `false` (`projectFile.ts:360-370`); the debounced timer ignores the return value (`projectStore.ts:334-336`). A long lecture's transcript plus 8 recent snapshots can approach the ~5 MB `localStorage` budget, after which edits stop being saved with no toast and no dirty-state change.
- `[INCOMPLETE — Low]` `.tafseer` stores `transcriptId`, but Step-2 discovery depends on the sidecar's in-memory store (already reported in Step 1 §B1) — the file round-trips the id without the data it points at. (Numeric-state consequences of corrupt inputs are covered in C7.)

#### C7. Clip math and degenerate numeric state

- `[BUG — Medium]` **An out-of-range proposal is turned into a fabricated clip instead of being dropped.** `normalizeSpeechRange` clamps both ends to the lecture and then enforces the 1 s minimum by *widening backwards* (`clipMath.ts:45-56`): a proposal of `50–60 s` against a `40 s` lecture becomes `{start: 39, end: 40}` — a clip invented at the tail of the video that the model never proposed. An entirely negative proposal becomes `{0, 1}` the same way.
- `[BUG — Medium]` **No finite guard in the buffer helpers.** `applyCutBuffer` and `speechFromCut` (`clipMath.ts:61-86`) pass values straight into `clamp`, which does not check `Number.isFinite` (`format.ts:3-5`), so a `NaN` speech bound or buffer yields `{start: NaN, end: NaN}` that is then persisted into the project and the `.tafseer`.
- `[BUG — Low]` **`speechFromCut` can return an inverted range.** With a 0.5 s cut and a 0.3 s buffer it returns `{start: 10.3, end: 10.2}` (`clipMath.ts:76-86`); only Step 2's immediate re-normalization (`Step2Discovery.tsx:510-513`) hides it.
- `[BUG — Low]` **With `duration === null` the auto-pad buffer is unbounded.** `clampToDuration` treats an unknown duration as `Infinity` (`clipMath.ts:31-34`), so a 100–105 s speech range with a 60 s buffer becomes `{40, 165}` with no media-length check.

#### B2. Faster-Whisper GTX VRAM Unloading (`backend/services/transcriber.py`)

3. **`[INCOMPLETE / LEAK — High]` `unload()` frees the Python object, but CUDA memory release has two subtle gaps.**
   - `WhisperTranscriber.unload()` (`backend/services/transcriber.py:310-326`) sets `self._model = None`, calls `gc.collect()`, and inside `try ... except Exception: pass` calls `torch.cuda.empty_cache()` and `torch.cuda.ipc_collect()`.
   - **Gap 1 — `ctranslate2` allocator is independent of PyTorch:** `faster-whisper` uses `ctranslate2.Translator` / `Whisper`, which manages its own CUDA device memory pool (caching allocator) in C++ (`libctranslate2`). Calling `torch.cuda.empty_cache()` only flushes **PyTorch's** caching allocator (and `torch` isn't even listed in `backend/requirements.txt:1-18`! Only `faster-whisper>=1.1,<2` is listed). While `del` + `gc.collect()` triggers CTranslate2's destructor, any reference cycle in an exception frame or `segments_iter` generator (`transcriber.py:341-365`) keeps the C++ model alive until the stack unwinds, and CTranslate2 may still hold CUDA context overhead (~200–400 MB) in the process.
   - **Gap 2 — Non-singleton `WhisperTranscriber` leaks if model load succeeds then inference fails or `/health` inspects stale singleton:** Look at `backend/main.py:455-468,491-504`: if the user changes `whisper.model` or `compute_type` in Settings (away from the env default `None`), `_engine_for()` allocates a **new** `WhisperTranscriber(...)` every call (`main.py:464-468`). Wait: `_engine_for()` uses a `try ... finally: if engine is not transcriber.get_transcriber(): engine.unload()` (`main.py:502-504`), so that temporary engine *is* unloaded when done, **even if `auto_unload=False`**! That means setting `auto_unload=False` with a custom model/compute_type silently ignores the user's toggle and reloads Whisper from scratch on every single transcription; conversely, if `body.model` matches the default and `body.model` string is sent by the frontend (`Step1Ingest.tsx:541` ALWAYS sends `model: settings.whisper.model` and `compute_type: settings.whisper.computeType`, never `null`!), **`_engine_for(body)` NEVER reuses the singleton** (`main.py:458-463` checks `body.model is None and body.device == "auto" and body.compute_type is None`)! So `_transcriber` in `GET /health` (`transcriber.py:472-488`) ALWAYS reports `loaded: false` even while a transcription is actively occupying VRAM, and `auto_unload=False` is defeated on every UI run.

#### B3. Zombie FFmpeg Subprocesses (`backend/services/renderer.py` & `transcriber.py`)
